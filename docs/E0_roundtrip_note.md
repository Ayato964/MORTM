# §9.12 トークナイザ往復テスト 結論（研究設計書 v1.3, 2026-07-10）

test: `tests/test_tokenizer_roundtrip.py`
不変量: MIDI → tokens → MIDI → tokens の冪等性。

## 結論: 粗い情報破壊なし。E0 の前提を満たす。

音符 26,256 個 / 40 曲での直接計測（パーサ非依存の多重集合比較）:

| 要素 | 往復挙動 | 判定 |
|---|---|---|
| **pitch（音高）** | **不一致 0 / 26,256 = 0.00%** | 完全可逆。`Pitch` は純粋パススルー(`note.pitch` ↔ `p_{n}`, キー相対/移調なし)なので構造上ズレない |
| shift-time（位置） | ±1 の丸め | 仕様（グリッド量子化）。学習は相対シンボリックでテンポ不使用 |
| duration（音長） | ±1（`Duration.get_token` の `int()` 切り捨て由来の浮動小数） | 亜知覚・学習不使用。encode 変更は学習済みモデルと不整合になるため行わない |

## 注意 / 既知の限界
- 生のトークン列**完全一致**率は低い（~9%）が、その大半は shift/duration の量子化 ±1 と、
  同時発音ノートの順序差である。**情報破壊ではない**。
- `<SME>`/`<BLANK>` による休符・長音符の小節またぎ表現があり、素朴な「SME を数えて
  小節番号を振る」パーサは小節番号を誤カウントしうる。往復の妥当性評価では
  **pitch 多重集合の一致**と**timing の ±1 許容**で判定するのが正しい（生列一致は不適）。
- 従って本テストの assert は「pitch 完全一致（構造忠実性）」を必須とし、timing は
  丸め許容とする方針。厳密な小節境界の復元テストは §9.7 T-noBar 実装時に別途整備。

## 帰結
トークナイザに往復バグ（特に pitch ドリフト）は無い。学習・生成に影響しない。
E0 以降の客観指標（decode→MIDI→計測）は pitch について信頼でき、timing は
グリッド ±1 の丸めを織り込んで解釈する。
